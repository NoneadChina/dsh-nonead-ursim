# 参考面板 → NoneadURSim 的功能落地方案

> 参考物：两张 PolyScope 截图（① 移动 tab：TCP/关节 jog + 刀具位置数值 + 底部状态/播放控制；② I/O tab：可配置/数字/模拟输入输出 + 工具 I/O + 模拟输出的电流域）。
> 本文回答"**怎么加进这个项目**"，不是"照着做一份 PolyScope"。范围 = 面板（`src/client/**`）与它需要的宿主通道（`lib/twin-routes.js` + `lib/index.js`），不动工具语义与审批门禁。
>
> ⚠️ 2026-10-15 起产品默认 `requireApprovalForMotion: false`（运动免人工确认）；本文中"真机动作必须走审批"的论述适用于**显式开启门禁**的部署。

---

## 0. 先定五条硬约束（后面每条设计都要过这五关）

| # | 约束 | 由来 | 对设计的影响 |
|---|---|---|---|
| C1 | **面板默认只读** | 项目从 0.7.0 起的定位：面板是"镜像真机"的只读视图 | 任何"写"都不能是顺手加个 onclick，必须走独立、可审计的写通道 |
| C2 | **写路由全局唯一且最严** | `POST /twin/sim` 是**唯一**写路由（`lib/index.js`），守卫 = 回环信任围栏 + `Origin` 必填 + `content-type: application/json` + ≤4 KB | 新增写能力要么扩这条，要么按同一套守卫**新开一条**，并在 README 的路由表登记 |
| C3 | **审批门不可绕过** | 真机模式下所有运动/程序类 op 走人工确认（`APPROVAL_OPS`）；面板不是例外 | 面板的 jog/播放**不能直连 worker**：必须复用工具执行路径（含审批），或**只在仿真目标**上放行 |
| C4 | **仿真能力边界写在代码里** | `sim_capabilities()` 已把"不支持"列成清单（力控/安全位/程序执行/原始脚本/传送带/电源刹车自由驱动/速度指令），面板有折叠块展示它 | 参考图里"不支持"的部分**如实标注 + 置灰**，不加假按钮；清单变化要同步 `tool-matrix` 与文案 |
| C5 | **面板在 DSH 右侧停靠栏，宽度约 300–400 px** | 参考图是 1694 px 宽的三栏布局 | **不能照搬三栏**。参考图 1 的"左 jab 区 + 中 3D + 右数值"必须改成**分页/分区**（见 §4 布局决策） |

## 2. 复用清单（先看有什么，再决定造什么）

**已有、直接用（不新增任何通道）**
- 读：`GET /twin/state`（位姿/型号）+ `&detail=1`（安全模式/运行态/速度倍率/温度/电流）+ `&io=1`（16 数字输出 + 16 数字输入 + 2 模拟输入）+ `&reg=int|double|bit&from=&count=`（寄存器分片）
- 流：`GET /twin/stream`（SSE，100 ms 一帧，面板默认走它）
- 仿真：`GET /twin/sim`（状态 + 能力清单 + 模式 + 白名单 + 落盘记忆）、`POST /twin/sim`（唯一写路由）
- 模型：`GET /twin/models`、`GET /twin/asset?model=`
- 工具（AI 侧已可用，面板只是**没有入口**）：`ur_move_x|y|z`、`move_tool_*`、`movej/movel`、`servoj`、`set_digital_out`、`set_analog_out`、`set_tcp`、`set_payload`、`wait_steady`、`stopj/stopl`、`load/run/pause/stop_program`、`set_freedrive/teach_mode`

**要新增（每条都要过 §0 的 C2/C3）**

| 通道 | 用途 | 守卫 | 备注 |
|---|---|---|---|
| `POST /twin/jog` | 点动：`{frame:'base'|'tool', axis:'x'|'y'|'z'|'rx'|.., step, continuous?}` | 同 `twin/sim` 的写守卫 | **只在仿真目标上放行**；真机目标直接 403 并提示"真机点动请让 AI 走审批"（C3） |
| `POST /twin/io` | 位/模拟输出写：`{kind:'digital_out'|'analog_out', n, value, full_scale?}` | 同上；**必须带上期望的当前值**（乐观锁，见 §5） | 真机侧：写 I/O **不是** `APPROVAL_OPS`（不动机器人），可放行，但要在 UI 上二次确认 |
| `POST /twin/speed` | 速度倍率写 | 同上 | ⚠️ **待确认**：项目当前只有 `get_speed_scaling`（读）。写需要新增 op（URScript/dashboard `set speed`）或扩展既有 op —— 这一条**先做调研再定**，不要先画 UI |
| `POST /twin/program` | 播放/暂停/停止 | 同上 + **必须过审批门** | 真机专用；仿真下按 C4 置灰 |

> 设计原则：**能复用工具 op 的，就不要在路由里另写一套**。路由只做「信任校验 + 参数白名单 + 转发到同一个 op 执行路径」，这样审批门、载荷指纹（M-1）、声明面白名单（H-1）全部自动生效。

## 3. 界面结构决策（本方案最关键的一条）

参考图是**宽屏三栏**；本项目面板是**窄侧栏**。照搬 = 每栏只剩 100 px、3D 视图被挤成邮票。因此：

```
┌─ NoneadURSim 面板（窄侧栏）──────────────┐
│ [监视] [移动] [I/O] [程序]   ← 分页 Tab   │  ← 一页只放一件事
├──────────────────────────────────────────┤
│  3D 视图（除"移动/程序"页外常显）          │
│  · 角标（三态模式）· 工具栏（视角）         │
├──────────────────────────────────────────┤
│  当前页内容（HUD 行 / jog 键盘 / I/O 表）  │
├──────────────────────────────────────────┤
│  底部常显条：状态灯 · 速度倍率 · 仿真开关   │
└──────────────────────────────────────────┘
```

- **常显**：3D 视图、三态模式角标、连接/风险状态、仿真开关（这些是"一眼必须看到"的）。
- **分页**：监视（现有 HUD：关节/TCP/遥测/风险/能力清单）、移动（P2/P3 的 jog）、I/O（P1）、程序（P5）。
- **分页状态记忆**：`localStorage`（与主题同一套轻量做法），别每次重开都回到第一页。
- **键盘**：jog 方向键 + Shift 加速 + 步长热键（1/2/3），这是 PolyScope 用户最熟的手感；无障碍上给每个按钮 `aria-label`。

## 4. 分批落地（每批独立可测、可发布、可回滚）

### P1 · I/O 页（性价比最高，先做）
- **范围**：数字输出 0–7 + 可配置输出 8–15（只读 + 写 8 位）、数字输入 16 位（只读）、模拟输入 2 路（只读，显示域）、模拟输出 2 路（滑块 + 工程单位 + 域）、工具遥测（工具输出电流/电压、I/O 电流；仿真下带 `estimated`）。
- **数据**：读走已有的 `&io=1`；工具遥测走 `get_tool_telemetry`（**新增**一个小通道或并入 `&io=1` 的响应）；写走新的 `POST /twin/io`。
- **交互**：位图上点一下切换 → 先本地乐观更新、请求成功落定、失败回滚并显示原因；**写请求带 `expect`（写前读到的值）**，服务器不匹配就拒绝（防两个面板互相覆盖）。
- **不改**：可配置输入（安全）只读且加锁图标；模拟**输入**域只显示不可改。
- **验收**：`io=1` 读的值与写后回读一致；写失败有可见原因；折叠/未打开时零请求（沿用 0.1.9 的按需纪律）；仿真下"输入恒 0"的说明仍在。

### P2 · 移动页：平移 jog + 目标位姿输入
- **范围**：6 向平移箭头（基座系 / 工具系切换）、步长选择（0.1/1/10 mm）、目标位姿输入（X/Y/Z/RX/RY/RZ → `movel`）、速度/加速度用工具的默认值。
- **数据/写**：`POST /twin/jog`（仿真目标直发；真机目标 403 + 提示走审批）。
- **实现**：每次点击 = 一步相对运动（`move_x` 等语义），**串行队列**（前一步没到位不发下一步，复用现有 `pending-motion` 的思路），到位判定用 `wait_steady` 的等价逻辑（速度阈值）。
- **验收**：连点 5 次 1 mm = 移动 5 mm（读回 TCP 验证）；运动中和运动后按钮状态正确；仿真下与画面一致。

### P3 · 移动页：旋转 jog + 关节微调
- **范围**：±RX/±RY/±RZ（工具系）、6 轴 ± 微调（步长 0.1°/1°/5°）、每轴滑条（拖动 = 目标关节角，松手才下发）。
- **验收**：姿态变化角度与步长一致（用 `fk` 独立校验）；关节微调后 `get_joint_pose` 与命令一致。

### P4 · 速度倍率 + 目标值表格
- **范围**：速度滑条（写）、"刀具位置/目标位姿"双列对比（**已有** `get_target_values`，面板只用读，很便宜）。
- **前置**：先解决"速度倍率怎么写"（§2 的待确认项）。若确实没有写 op，就先只做**目标值对比**，滑条留到补上 op 之后 —— 宁可少一个控件，不做一个假控件。

### P5 · 程序控制（真机专用）
- **范围**：播放/暂停/停止（+ 程序名列表 `list_programs`/`load_program`）。
- **铁律**：这些是 `APPROVAL_OPS` 覆盖的动作 ⇒ 面板**不得**自己下发，必须走"面板请求 → 宿主转成待审批动作 → 人工确认 → 下发"。仿真下整页置灰并写明"仿真没有程序执行语义"。
- **风险**：这是整个方案里**唯一能真的让真机动起来的**新入口，建议单独一轮、单独评审。

## 5. 安全与边界（不写进代码就会被后人忘掉的四条）

1. **安全 I/O 只读**：可配置输入/输出（S-Guard 等）是安全功能配置，改它等于改安全策略。面板只展示 + 标注"请在示教器上修改"。
2. **工具端 I/O 的副作用要说清**：`get_digital_in(which="tool")` / `get_tool_analog_in` 会向控制器发一段短 URScript，**可能打断正在运行的程序**（0.1.9 已因此避开）。若要做成按钮，必须**单次、显式、带提示**，绝不随刷新轮询。
3. **写请求带期望值（乐观锁）**：两个面板同时开是常态。没有 `expect` 的 I/O 写会互相覆盖，而操作员看到的还是自己的旧画面。
4. **真机与仿真分道**：面板的新写通道**只对仿真目标放行**（`127.0.0.1`）；真机的一切运动/程序动作仍走工具 + 审批。这样"面板变强"不会悄悄削弱门禁。

---

## 6. 明确不做（写下来是为了以后不被反复提起）
- 力控、安全状态位配置、原始 URScript 下发、传送带控制、电源/刹车/自由驱动/示教等机械状态变更（仿真无语义；真机侧请用 PolyScope）。
- "特征/主动 TCP"这类 PolyScope 的坐标系体系（本项目只做基座/工具两系）。
- 三段式宽屏布局、程序树编辑、安装向导。
